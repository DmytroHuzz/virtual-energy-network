# From one LAN to a network of networks

Let's add a second bay. It has the same interface names and programs, but a separate Sensor LAN. Only the two logical devices join the operator LAN.

```bash
for device in lab-s2 lab-ld2 lab-led2; do
  ip netns add "$device"
  ip -n "$device" link set lo up
done
ip link add br-s2 type bridge
ip link set br-s2 up
for pair in s2:lab-s2 ld2:lab-ld2 led2:lab-led2; do
  port=${pair%%:*}
  device=${pair#*:}
  ip link add "$port-p" type veth peer name "$port-n"
  ip link set "$port-n" netns "$device"
  ip -n "$device" link set "$port-n" name eth0
  ip -n "$device" link set eth0 up
  ip link set "$port-p" master br-s2
  ip link set "$port-p" up
done
ip link add br-op type bridge
ip link set br-op up
ip link set op1-p master br-op
ip link add op2-p type veth peer name op2-n
ip link set op2-n netns lab-ld2
ip -n lab-ld2 link set op2-n name eth1
ip -n lab-ld2 addr add 10.20.0.12/24 dev eth1
ip -n lab-ld2 link set eth1 up
ip link set op2-p master br-op
ip link set op2-p up
bash lab.sh start 2
sleep 2
bash lab.sh status lab-ld2 10.20.0.12
```{{exec}}

LD2 should report a **local** alarm of `False` and a **global** alarm set containing `LD1`. LED2 stays off. Receiving another bay's alarm does not turn on its own local LED.

Capture the operator traffic:

```bash
ip netns exec lab-ld2 timeout 8 tcpdump -l -ni eth1 -A -c 4 'udp port 10000'
```{{exec}}

Here the alarm text travels in **UDP/IP multicast**, to `224.0.0.1:10000` with TTL 1. Compare that with the experimental Ethernet frames in step 3. `224.0.0.1` is the all-hosts link-local group; it stays on this LAN. We are not building multicast routing.

Try bay 2 at 15, inspect both LEDs and status responses, then restore it to 5:

```bash
bash lab.sh voltage 2 15
sleep 2
bash lab.sh status lab-ld1 10.20.0.11
tail -n 2 run/led2.log
bash lab.sh voltage 2 5
sleep 2
bash lab.sh status lab-ld2 10.20.0.12
```{{exec}}

**Explain:** why can LD2 know about LD1's alarm while Sensor2 never receives Sensor1's measurement?

The shared state is refreshed once per measurement; this example has no expiry or reliable event log. Stopping a sender can leave stale global state. A production design needs explicit liveness and recovery behavior.
