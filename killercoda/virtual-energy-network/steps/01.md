# Give every device a network stack

One machine normally has one view of network interfaces, routes and sockets. Our sensor and logical device must behave like different devices. A network namespace gives each one its own view.

First inspect the host:

```bash
cd /root/energy-lab
ip -br link
ip route
```{{exec}}

Create three devices. Bring up their loopback interfaces:

```bash
for device in lab-s1 lab-ld1 lab-led1; do
  ip netns add "$device"
  ip -n "$device" link set lo up
done
ip netns list
ip -n lab-s1 -br link
```{{exec}}

**Predict:** does `lab-s1` see the host's Ethernet interface? Why can't it communicate with `lab-ld1` yet?

`ip -n NAME` inspects that namespace. `ip netns exec NAME COMMAND` runs a process with that namespace's network stack. Files remain shared:

```bash
ip netns exec lab-s1 ls /root/energy-lab
```{{exec}}

All three devices see the same Python files, but only their own interfaces. Containers build on these primitives and add other isolation mechanisms.
