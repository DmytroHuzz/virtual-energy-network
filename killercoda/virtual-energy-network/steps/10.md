# Diagnose a link fault and a routing fault

**Goal:** use evidence to distinguish a stale application state, a stopped listener and an incomplete packet path.

Return to one terminal for these exercises. Both tabs run in the same host namespace unless a command explicitly selects another namespace.

## Fault 1: the local indicator loses its connection

Bay 1 starts high and LED1 is on. **Predict:** if only the LED's interface goes down, can the sensor and logical device still talk? Can the supervisor still query LD1?

```bash
cd /root/energy-lab
ip -n lab-led1 link set eth0 down
bash lab.sh voltage 1 5
sleep 2
bash lab.sh status lab-sup 192.0.2.10
tail -n 4 run/led1.log
```{{exec}}

**Expected:** LD1 clears its local alarm, and the supervisor can read it. LED1 stops receiving commands. Its last logged state can therefore disagree with LD1's current decision. The small raw-socket LED program can exit with `OSError: Network is down`; the log may end in that error instead of a new state message.

Inspect the link and processes rather than assuming the application is still alive:

```bash
ip -n lab-led1 -br link show eth0
ip netns pids lab-led1
```{{exec}}

The interface is administratively down. If the listener exited, its Python PID is absent. A successful status query to LD1 does not prove delivery to LED1.

Restore the interface and restart any exited LED process:

```bash
ip -n lab-led1 link set eth0 up
bash lab.sh start 1
sleep 2
tail -n 2 run/led1.log
```{{exec}}

**Expected:** `Turning LED off LED1`. The helper leaves still-running applications alone. Repeated measurements and commands let the restarted LED catch up; this behavior depends on the application publishing current state repeatedly.

Restore bay 1's high input before the next fault:

```bash
bash lab.sh voltage 1 15
sleep 2
```{{exec}}

## Fault 2: the request has a path but the reply does not

Remove only LD1's default route, then make a new supervisor connection:

```bash
ip -n lab-ld1 route del default
if bash lab.sh status lab-sup 192.0.2.10; then
  echo 'Unexpected: investigate whether another return route exists'
else
  echo 'Expected: the TCP query did not complete'
fi
```{{exec}}

**Expected:** a bounded timeout from the status client. The gateway can still translate and forward the TCP connection attempt (the SYN packet). LD1 has lost its path back to `192.0.2.2`, so even the connection handshake cannot complete; the application-level `GET` is not delivered.

Compare the route decisions in the two stacks:

```bash
ip -n lab-gw route get 10.20.0.11
ip -n lab-ld1 route get 192.0.2.2 || echo 'Expected: LD1 has no return route'
```{{exec}}

This is why checking only the gateway's table is insufficient. NAT changes addresses; it does not supply a missing route in the endpoint.

Repair and verify:

```bash
ip -n lab-ld1 route add default via 10.20.0.1
bash lab.sh status lab-sup 192.0.2.10
bash lab.sh status lab-sup 192.0.2.11
```{{exec}}

**Expected:** both devices respond again, LD1 has a local alarm, and LD2 knows LD1's alarm while its own local alarm stays clear.

## A repeatable investigation order

| Question | Useful observation |
|---|---|
| Am I looking at the right device? | Prefix `ip` with `-n NAME`, or run the tool with `ip netns exec NAME` |
| Is the cable enabled at both ends? | `ip ... link show` in each owning namespace |
| Is the port on the intended switch? | `bridge link show master BRIDGE` in the host |
| Does the process exist and listen? | `ip netns pids NAME`, application logs, `ip netns exec NAME ss -lnt` for TCP |
| Can both directions find a route? | `ip -n NAME route get DESTINATION` at each endpoint and the router |
| Where does the packet stop or change? | `tcpdump` in the relevant namespace and gateway rule counters |

Leave bay 1 at 15 and bay 2 at 5, with both faults repaired. Click **Check** for the final end-to-end check. You do not need to reset before checking.

To repeat from an empty topology later, run `bash /root/energy-lab/lab.sh reset` and return to lesson 1. Reset removes this lab's processes, namespaces, bridges and generated state; it does not undo only the last lesson.
