# Build the supervisor's network before routing it

**Goal:** give the supervisor and gateway interfaces on two distinct IP networks.

So far, operator messages stay inside `10.20.0.0/24`. Put the supervisor on `192.0.2.0/24`, connected to the gateway by a direct veth pair. The gateway will have an interface in each subnet.

```text
LD1 .11 ─┐
         br-op ─ gateway eth0 .1 | eth1 .1 ===== supervisor eth0 .2
LD2 .12 ─┘
       10.20.0.0/24                          192.0.2.0/24
```

Both `.1` addresses are valid because they belong to different subnets. The WAN addresses are reserved documentation addresses inside the lab, not actual Internet-facing public addresses.

| Namespace | Interface | Address | Connection |
|---|---|---|---|
| `lab-gw` | `eth0` | `10.20.0.1/24` | `br-op` through `gw-p` |
| `lab-gw` | `eth1` | `192.0.2.1/24` | Direct veth to supervisor |
| `lab-sup` | `eth0` | `192.0.2.2/24` | Direct veth to gateway |

Create their network stacks:

```bash
ip netns add lab-gw
ip -n lab-gw link set lo up
ip netns add lab-sup
ip -n lab-sup link set lo up
```{{exec}}

Connect the gateway to the operator LAN:

```bash
ip link add gw-p type veth peer name gw-n
ip link set gw-n netns lab-gw
ip -n lab-gw link set gw-n name eth0
ip -n lab-gw addr add 10.20.0.1/24 dev eth0
ip link set gw-p master br-op
ip -n lab-gw link set eth0 up
ip link set gw-p up
```{{exec}}

Now create a cable with **both ends inside device namespaces**. A veth pair does not require an end in the host:

```bash
ip link add wan-g type veth peer name wan-s
ip link set wan-g netns lab-gw
ip link set wan-s netns lab-sup
ip -n lab-gw link set wan-g name eth1
ip -n lab-sup link set wan-s name eth0
```{{exec}}

Assign the WAN addresses and enable the ends:

```bash
ip -n lab-gw addr add 192.0.2.1/24 dev eth1
ip -n lab-sup addr add 192.0.2.2/24 dev eth0
ip -n lab-gw link set eth1 up
ip -n lab-sup link set eth0 up
ip -n lab-gw -br address
ip -n lab-sup -br address
```{{exec}}

**Expected:** the gateway has one address on each subnet; the supervisor has only a WAN address. Unlike a bridge, the router uses its interface IP addresses as reachable next hops.

Ask the supervisor's kernel how it would reach each destination. `route get` looks up a route; it does not send a test packet:

```bash
ip -n lab-sup route get 192.0.2.1
ip -n lab-sup route get 10.20.0.11 || echo 'Expected: no route to the operator subnet yet'
```{{exec}}

**Expected:** the gateway's WAN address is directly reachable through `eth0`, but LD1's private address is not. Having a cable to a dual-interface machine does not automatically install routes or turn it into a router.
