# A virtual cable and a virtual switch

A **veth pair** is a cable with two interfaces. Frames transmitted at one end arrive at the other. A Linux **bridge** connects multiple cable ends like an Ethernet switch.

Build the first Sensor LAN:

```bash
ip link add br-s1 type bridge
ip link set br-s1 up
for pair in s1:lab-s1 ld1:lab-ld1 led1:lab-led1; do
  port=${pair%%:*}
  device=${pair#*:}
  ip link add "$port-p" type veth peer name "$port-n"
  ip link set "$port-n" netns "$device"
  ip -n "$device" link set "$port-n" name eth0
  ip -n "$device" link set eth0 up
  ip link set "$port-p" master br-s1
  ip link set "$port-p" up
done
bridge link show master br-s1
```{{exec}}

Names ending in `-p` are the host-side bridge ports. Each device sees its own `eth0`. The same interface name can exist in different namespaces.

No IP addresses are needed here. Our sensor publishes **Ethernet frames** to multicast MAC `03:00:00:00:00:01`, with experimental EtherType `0x88b5`. That frame format belongs to this tutorial.

Observe the new network:

```bash
ip -n lab-ld1 -br link
bridge fdb show br br-s1
```{{exec}}

The forwarding database learns source MAC addresses as traffic arrives. It is not an IP routing table.
