# Make one cable and follow both ends

**Goal:** create a virtual Ethernet connection without hiding the operations in a loop.

A **veth pair** has two linked interfaces. A frame sent through one end arrives at the other. Think of it as a cable with a network interface at each end; it does not create a switch or a route.

Create both ends in the host namespace:

```bash
ip link add s1-p type veth peer name s1-n
ip -br link show s1-p
ip -br link show s1-n
```{{exec}}

The names are our convention: `-p` will be the switch-side **port** in the host, and `-n` is the end we will move into the device's **namespace**. Linux does not assign these meanings to the suffixes.

Move only `s1-n` into the sensor:

```bash
ip link set s1-n netns lab-s1
ip -n lab-s1 -br link
```{{exec}}

**Expected:** the sensor now sees `lo` and `s1-n`. The host still owns `s1-p`, but no longer lists `s1-n` among its own interfaces. Moving one end does not break the pair.

Give the device-side interface the name that the Python program will use:

```bash
ip -n lab-s1 link set s1-n name eth0
ip -n lab-s1 link set eth0 up
ip link set s1-p up
```{{exec}}

Both ends need to be administratively up. With both ends enabled, the pair should have a carrier (`LOWER_UP`). An `@if...` suffix in output identifies a peer by interface index; it is not part of the name you type.

```bash
ip -n lab-s1 -br link show eth0
ip -br link show s1-p
ip -n lab-s1 -4 address show dev eth0
```{{exec}}

**Expected:** the sensor's `eth0` and the host's `s1-p` are up. There is no IPv4 address on `eth0`. That is fine: an Ethernet connection can exist before IP is configured.

```text
lab-s1 namespace                  host namespace
Sensor1 -> eth0 ===== veth pair ===== s1-p
```

The host end is not attached to anything else yet. Enabling a cable is different from connecting several devices into a LAN.

Click **Check** to verify both ends. If one is down, inspect it in the namespace that owns it.
